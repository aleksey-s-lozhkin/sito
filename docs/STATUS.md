## Документация: что считается устаревшим и как это замечать

Правило: **документ, описывающий прежнее устройство, хуже отсутствующего** — он
врёт с уверенностью, и по нему принимают решения. Устаревшим считается всё, что
называет:

- **модель, которой больше нет.** `nomic-embed-text` заменён на `bge-m3` — в коде
  второй, а документация может ещё описывать первый (`RAG-EXPERIMENT.md` пишет о
  нём как о прошлом — это законно, записи о прошлом не переписываются);
- **команду, индекс или поле, которых нет либо которые только появились.**
  Новое: `embed_chunks`, `describe_unreadable_documents`, `dense_vector` в
  `chunks`;
- **значение поля или форму ответа.** `score` теперь `null`; схема API
  генерируется из сериализатора, поэтому расхождение ловится в CI;
- **число** — тесты, куски, знаки. Числа устаревают первыми, поэтому их пишут с
  оговоркой «на момент замера» или не пишут вовсе;
- **«сделаем» там, где уже сделано** — и наоборот. План, выполненный с
  отклонениями, обязан это сказать: у RAG-EXPERIMENT.md приёмка была 6/7
  перефразированных, получилось 5/7.

**Как замечать.** Автоматика ловит ровно одно: `docs/api/openapi.json` CI сверяет
с генерацией из кода. Остальное — глазами, и дешёвый способ такой: перед PR
пройти по документам и сверить имена, которые встречаются в коде, — моделей
(`OLLAMA_*` в `config/settings.py`), команд (`documents/management/commands/`),
индексов и полей (`documents/documents.py`), констант (`VECTOR_MIN_SCORE`,
`RRF_K`, `MAX_CHUNKS_PER_DOCUMENT`). По имени расхождение находится за минуту;
без имени — не находится никогда.

**Что осталось за документами** (правками документов не решается — нужно решение
по коду или по репозиторию):

1. Нет тестов на `embedding_service`, `embed_chunks`, слияние по рангам и
   `describe_unreadable_documents`; отдельно об этом — долг №6 выше.
2. Замер на 329 кусках собирается скриптом `tools/build_distractor_corpus.py`.
   Прогон **не воспроизводится байт-в-байт**: страницы меняются, Википедия
   отвечает 429. Отсюда порядок: **сначала замер, потом пересборка индекса** —
   заново тот же корпус не собрать, и сравнивать будет не с чем.

поиска (#113). 7 ноября — актуализация после #115–#119: STATUS, README

## Как проверять вручную

- Интерфейс: эмулятор Android, рецепт в [CLAUDE.md](../CLAUDE.md).
- API: `curl` с токеном потребителя к `/api/v1/search/retrieve`; без токена — 401,
  с `user_id` в теле — 400, пустой результат — 200 с пустым списком.
- Тексты: `manage.py reextract_text --dry-run` показывает, что изменится.
- Языковая модель: `manage.py summarize_documents --limit 3 --dry-run`.
- Вектора: `manage.py embed_chunks` без флагов — берёт только куски без векторов,
  поэтому повторный запуск ничего не пересчитывает; после смены модели эмбеддингов
  нужен `--force`. Сколько векторов на месте, видно запросом из OPERATIONS.md,
  «Поиск отвечает по словам».
- Документы без текста: `manage.py describe_unreadable_documents` показывает
  найденные заголовки и ничего не пишет; записывает только с `--apply`.
- Гибридный поиск: смотреть `source` в ответе эндпоинта (`hybrid` / `vector` /
  `fulltext`) — по нему видно, работала ли векторная половина.
- Боевой прогон гибрида: выпустить временный служебный токен
  (`manage.py issue_api_token --name qa --scope service`), дёрнуть
  `/api/v1/search/retrieve`, посмотреть `source`, затем отозвать
  (`--revoke ID`): значение показывается один раз.
- Прод: `ssh -p 2222 alserloz@infra-dev`; локально имя `infra-dev` не резолвится —
  хост в `known_hosts` записан как `95.54.44.225` (см. CLAUDE.md, «Окружение»).
